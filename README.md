# Qonaq Vision

**Қонақ — «гость».** Видеоаналитика зала ресторана (и зоны ожидания клиники) поверх камер, которые
у вас уже висят. Система видит каждый стол как зону и в реальном времени знает: стол свободен →
гости сели и ждут официанта → их обслуживают → ушли, стол не убран. Из этих событий считаются
время подхода официанта, простой неубранных столов, оборачиваемость и **потери в тенге**.

- Без новых датчиков: используются существующие камеры и регистратор (Hikvision, Dahua, XMeye, Uniview…).
- Без облака: всё считается на ПК в заведении, наружу уходят только цифры и алерты в Telegram.
- Без распознавания лиц: люди — анонимные рамки; сохраняемые ролики — только с размытыми лицами.

> Статус: MVP. Что реально проверено и где система ошибается — в [docs/EVAL.md](docs/EVAL.md).
> Что готово и что показывать — в [PROGRESS.md](PROGRESS.md).

## Установка (Windows и Linux)

Нужен Python 3.11 или 3.12.

```bash
git clone <адрес репозитория> qonaq
```
```bash
cd qonaq
```
```bash
python -m venv .venv
```

Активировать окружение — Windows (PowerShell):

```powershell
.venv\Scripts\Activate.ps1
```

Linux / macOS:

```bash
source .venv/bin/activate
```

Поставить зависимости (без PyTorch — детектор работает через onnxruntime, установка занимает минуту):

```bash
pip install -e ".[dev]"
```

Необязательно — детектор Ultralytics YOLO (нужен PyTorch; с видеокартой NVIDIA сначала поставьте
CUDA-сборку PyTorch с pytorch.org). Если он установлен, система выберет его автоматически:

```bash
pip install -e ".[yolo]"
```

## 5 команд для старта

```bash
python scripts/fetch_videos.py
```
```bash
python -m qonaq doctor
```
```bash
python -m qonaq zones suggest data/videos/cctv_terrace_cafe.mov
```
```bash
python -m qonaq demo data/videos/cctv_terrace_cafe.mov
```
```bash
python -m qonaq report runs/cctv_terrace_cafe
```

1. скачивает 5 тестовых записей в `data/videos/` (в git они не попадают);
2. проверяет Python, детектор, GPU, ffmpeg, найденные видео;
3. сам предлагает зоны столов → `configs/zones/<имя видео>.yaml` и превью в `runs/zones/`;
4. делает демо-ролик `runs/<имя>/demo.mp4`: цветные столы, таймеры, боковая панель, лица размыты;
5. строит отчёт смены: `report.html`, `report.md` и короткий `telegram.txt`.

На своём видео — то же самое, подставьте путь к файлу.

### Вебкамера ноутбука (live)

```bash
python -m qonaq live --site configs/sites/demo_webcam.yaml
```

Откройте http://127.0.0.1:8000 — кадр с камеры, статус стола, таймеры, лента алертов.
В этом конфиге пороги укорочены (сел на 5 секунд — «ждут официанта», алерт через 30 секунд),
чтобы всё было видно сразу. Без камеры то же можно посмотреть на записи, проигрываемой «как поток»:

```bash
python -m qonaq live --site configs/sites/demo_file_as_stream.yaml
```

## Все команды

| Команда | Что делает |
|---|---|
| `python -m qonaq doctor` | проверка окружения |
| `python -m qonaq run-file <видео>` | отладочное видео: рамки, id треков, роли + журнал событий |
| `python -m qonaq zones suggest <видео>` | авто-предложение столов |
| `python -m qonaq zones edit <видео\|картинка>` | редактор зон в окне |
| `python -m qonaq zones preview <видео>` | PNG кадра с зонами |
| `python -m qonaq roles calibrate <видео>` | калибровка формы персонала |
| `python -m qonaq demo <видео>` | демо-ролик «как в рилсе» (`--speed 4`, `--loops 3`) |
| `python -m qonaq report <папка прогона>` | отчёт смены |
| `python -m qonaq live --site <yaml>` | поток + веб-панель + алерты |
| `python -m qonaq eval <папка прогона>` | сверка событий с ручной разметкой |
| `python scripts/run_all.py` | всё сразу на всех видео из `data/videos/` |

Общие флаги: `--fps 3` (кадров в секунду), `--model yolox_m --tiles 2` (точнее, но в ~6 раз медленнее),
`--site configs/sites/x.yaml` (пороги, средний чек), `--max-seconds 30`.

## Как подключить камеры Hikvision / Dahua

Система читает RTSP-поток регистратора или камеры. Берите **substream** (второй поток,
640×360…704×576): его хватает, и он не грузит регистратор.

| Производитель | Адрес (substream) |
|---|---|
| Hikvision / HiWatch | `rtsp://USER:PASS@IP:554/Streaming/Channels/102` (канал 1; `202` — канал 2; `101` — основной поток) |
| Dahua / Imou | `rtsp://USER:PASS@IP:554/cam/realmonitor?channel=1&subtype=1` (`subtype=0` — основной) |
| XMeye / iCSee | `rtsp://IP:554/user=USER&password=PASS&channel=1&stream=1.sdp?real_stream` |
| Uniview | `rtsp://USER:PASS@IP:554/unicast/c1/s1/live` |

1. Проверьте адрес в VLC: «Медиа → Открыть URL». У прошивок бывают отличия.
2. Скопируйте `.env.example` в `.env` и впишите логин/пароль (`CAM_USER`, `CAM_PASS`).
   **Пароли — только в `.env`**, в YAML пишется `${CAM_USER}:${CAM_PASS}`.
3. Скопируйте `configs/sites/clinic_example.yaml` (или `demo_webcam.yaml`), впишите адрес в `source:`.
4. Сделайте снимок с камеры и разметьте зоны (см. ниже). Запустите `live --site ваш.yaml`.

При обрыве потока система переподключается сама (задержка растёт: 1, 2, 4… до 30 секунд).
Подробный чек-лист выезда на объект — [docs/INSTALL_ONSITE.md](docs/INSTALL_ONSITE.md).

## Как разметить зоны

Зона — многоугольник на кадре: `table` (стол **вместе со стульями**), `entrance` (вход/очередь),
`waiting_area`, `service_point` (стойка), `ignore` (где людей не считать: проход, улица, телевизор).

1. Черновик: `python -m qonaq zones suggest <видео>` — находит столы детектором и рисует прямоугольники.
   Это именно черновик: на косых камерах столы находятся не все, а рамки грубые (см. EVAL.md).
2. Правка в окне: `python -m qonaq zones edit <видео>`
   — клик ставит вершину, **Enter** закрывает многоугольник, **Backspace** отменяет,
   **t** меняет тип зоны, **n** даёт имя, **s** сохраняет, **q** выходит.
3. Или руками в YAML (`configs/zones/<камера>.yaml`) — формат простой:

```yaml
camera_id: hall
frame_size: [1920, 1080]        # размер кадра при разметке; под другой размер пересчитается само
zones:
- id: T01
  type: table
  name: У окна
  polygon: [[1250, 430], [1500, 430], [1580, 640], [1300, 640]]
```

4. Проверка: `python -m qonaq zones preview <видео>` → `runs/zones/<имя>.png`.

Совет: полигон стола должен накрывать сидящих людей целиком (на косой камере — выше столешницы).

## Как читать отчёт

`runs/<прогон>/report.html` открывается в браузере, рассчитан на человека без технической подготовки.

- **Гости ждут официанта (медиана)** — половина столов дождалась быстрее этого времени.
  p90 — «9 столов из 10 ждали не дольше».
- **Ждали дольше 3 минут** — доля столов с долгим ожиданием. Это будущие плохие отзывы в 2ГИС.
- **Ушли, не дождавшись** — сели и ушли до подхода официанта.
- **Стол не убран** — сколько стол стоит грязным после ухода гостей.
- **Потери в ₸** — считаются консервативно: только лишний простой неубранного стола **в пиковое время**
  (зал загружен ≥ 80% или у входа очередь), сверх норматива уборки. В пустом зале грязный стол денег не стоит.
  Средний чек задаётся в YAML объекта (`business.avg_check_kzt`) или флагом `report --avg-check 18000`.
- **Насколько этим цифрам можно верить** — обязательно прочитайте этот блок: в нём сказано, сколько
  данных в основе и какие оценки менее надёжны (например, без калибровки формы персонала).

## Настройки объекта

Один YAML на объект (`configs/sites/*.yaml`) — единственный источник правды: камеры, профиль
(`restaurant` / `clinic`), пороги, пути к зонам, средний чек, часы работы. Пороги по умолчанию:
сели — 15 с, визит персонала — от 4 с, ушли — 90 с без гостей, уборка — от 10 с;
алерты: 3 мин без официанта, 5 мин неубранный стол, 15 мин без внимания.

Алерты в Telegram включаются, если в `.env` заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
Без них всё работает, алерты видны в панели и в логе.

## Приватность

- Лица не распознаются, люди не идентифицируются; id треков анонимны и живут в пределах сессии.
- Сырое видео не сохраняется. Любой сохраняемый кадр или ролик — с размытием голов (включено по умолчанию).
- Размытие опирается на детектор: человека, которого детектор не увидел, оно не закроет.
  **Перед показом ролика кому-либо просмотрите его целиком.**

- Детектор по умолчанию без PyTorch — YOLOX (Apache-2.0) через onnxruntime (MIT).

  детектора. Он подключён только через адаптер `qonaq/detect/ultra.py` (см. [DECISIONS.md](DECISIONS.md)).
