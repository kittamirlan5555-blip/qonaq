## Что запустить на ноутбуке (MacBook M1 Pro / Windows + RTX 2060 Super)

```bash
git pull && python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\Activate.ps1
pip install -e ".[dev]"
python -m qonaq doctor
python scripts/fetch_videos.py
```

Постановочный тест (11 минут записи, 2 человека) — по `docs/STAGED_TEST.md`:

```bash
python -m qonaq record --source webcam:0 --seconds 660 --out data/videos/staged.mp4
python -m qonaq staged-check data/videos/staged.mp4 --gt data/gt/staged.yaml
```

Калибровка на своей записи (проверка всего пути установки):

```bash
python -m qonaq calibrate collect data/videos/staged.mp4 --site-id home
python -m qonaq calibrate review --site-id home        # http://127.0.0.1:8010, клики 1/2/0
python -m qonaq calibrate train --site-id home         # «было X% → стало Y%»
python -m qonaq calibrate promote --site-id home       # затем roles.classifier: models/site/home/active.npz
```

Синтетика и обучение (нужны датасеты, ~1 ГБ):

```bash
python scripts/fetch_datasets.py && python scripts/fetch_models.py && python -m qonaq data index
python -m qonaq train roles && python -m qonaq calibrate curve && python -m qonaq synth
```

На Windows с RTX 2060 Super: `pip install onnxruntime-gpu` (вместо `onnxruntime`) — YOLOX и энкодер пойдут на CUDA.

## Цифры сверки с ручной разметкой

Команда `python -m qonaq eval runs/<имя>`, совпадение = тот же тип события и та же зона в окне ±10 с.
Детектор `yolox_m` + плитки, 4 кадр/с, зоны поправлены вручную.

**Это очень маленькая выборка: 10 размеченных событий на двух роликах по 60–88 с, один разметчик.
Называть это «точностью системы» нельзя — только «на этих двух роликах получилось так».**

`cctv_restaurant_corner` (содержательная часть 0–48 с):

|---|---|---|---|---|---|---|
| seated | 5 | 4 | 4 | 1.00 | 0.80 | 4.70 |
| staff_visit | 1 | 0 | 0 | — | 0.00 | — |
| ВСЕГО | 6 | 4 | 4 | 1.00 | 0.67 | 4.70 |

Пропущено: посадка за T04 (стол у правого края кадра, люди видны частично) и визит официанта к T03 на 4-й секунде
(он случился раньше, чем система подтвердила, что стол занят, — на это нужно 15 с).

`cctv_terrace_cafe` (88 с):

| Событие | В разметке | У системы | Совпало | Precision | Recall | Ошибка времени, с |
|---|---|---|---|---|---|---|
| seated | 4 | 4 | 4 | 1.00 | 1.00 | 0.51 |
| staff_visit | 0 | 1 | 0 | 0.00 | — | — |
| ВСЕГО | 4 | 5 | 4 | 0.80 | 1.00 | 0.51 |

Лишнее событие: визит персонала к T01 на 40-й секунде. **Возможно, ошибается разметка, а не система:**
при увеличении видно, что у дальнего стола примерно с 30-й по 57-ю секунду стоит и наклоняется мужчина
в белой рубашке и кепке, похожий на официанта. Разметку я не менял — цифра оставлена как получилась.

Что из этого следует:
- Посадки (в обоих роликах это «уже сидели на старте») находятся хорошо: 8 из 9.
- **Визиты персонала на этих роликах не подтверждены ни одним верным срабатыванием** (0 совпадений).
  До правки «визит неизвестного — только если он стоит» было 3 ложных визита на двух роликах, после — 1 спорный.
- События «подошёл официант», «ушли», «убрали», «ушли не дождавшись» **на реальном видео не проверены вообще**:
  в роликах их нет (нужно ≥ 90 с пустого стола). Они проверены только синтетикой и сквозным тестом
  на сценарном детекторе (`tests/test_pipeline.py`).

## Скорость (CPU, 4 ядра, без GPU)

| Режим | Кадр/с обработки | Относительно реального времени |
|---|---|---|
| `yolox_s`, без плиток, 5 кадр/с (по умолчанию) | 9–10 | ×1,8–2,0 быстрее (замерено на 3 видео из 5) |
| `yolox_m` + плитки, 4 кадр/с (качество) | 1,6–1,8 | ×0,40–0,44, т.е. медленнее реального времени (все 5 видео) |

Лёгкая модель на тёмной угловой записи ресторана почти не видит людей (0 треков на проверенном кадре,
часть лиц осталась неразмытой). Тяжёлый режим видит 6 человек на том же кадре, но в реальном времени
на CPU не успевает. Для live на CPU остаётся только лёгкая модель.

## Какой демо-ролик показывать

**`runs/cctv_terrace_cafe/demo.mp4`** — веранда, 88 с, боевые пороги. Картинка чистая: синие занятые столы

## Известные баги

1. **[ИСПРАВЛЕН в `b40477f`, D-012]** **Ложные «ушли не дождавшись» при `preexisting_grace_s: 0`** — затрагивает `demo_webcam.yaml` и `demo_fast.yaml`.
   Найден на прогоне `terrace_fast`: стол трижды подряд проходит «сели → ушли не дождавшись → сели» с временем
   ожидания −0,5 с. Причина: сразу после посадки фильтр присутствия гостей ещё выключен, а его отметка
   «пусто с…» указывает на старт потока, поэтому таймер ухода срабатывает мгновенно
   (`qonaq/logic/restaurant.py`, `_step_waiting`). На вебкамере это проявится, если сесть позже чем через 15 с
   после запуска. С боевыми порогами (`preexisting_grace_s: 30`) на прогонах не наблюдался, но логически возможен.
2. Отчёт по прогону с этим багом считает ложные уходы в потери.

## Блокеры и обходные пути

- **PyTorch.** `download.pytorch.org` закрыт сетевой политикой; сборка с PyPI (с CUDA-библиотеками) качалась
  несколько часов и в итоге поставилась в `.venv`. **Адаптер Ultralytics (`qonaq/detect/ultra.py`) так ни разу
  и не запускался** — весь прогон сделан на YOLOX через onnxruntime (DECISIONS D-003).
  Тесты гонялись во временном окружении без torch; в `.venv` проекта тесты не запускались.
- Тестовые ролики короткие и статичные — длинные сценарии проверены только синтетикой.
