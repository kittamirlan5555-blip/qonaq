# Постановочный тест на ноутбуке (10 минут)

Цель — впервые проверить на «живой» записи то, что пока проверено только синтетикой: подход официанта,
временный уход гостя, уход, «стол не убран», уборка. Нужны 2 человека: «гость» и «официант».

## 1. Установка (один раз)

MacBook (M1 Pro) или Windows-ПК. Python 3.11/3.12.

```bash
git clone https://github.com/kittamirlan5555-blip/qonaq.git && cd qonaq
git checkout claude/bold-fermat-de51i5
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -e ".[dev]"
python -m qonaq doctor
```

**macOS, разрешение на камеру.** При первой записи macOS спросит доступ к камере для приложения,
из которого запущена команда (Terminal, iTerm, VS Code). Если окно не появилось или кадр чёрный:
Системные настройки → Конфиденциальность и безопасность → Камера → включить для этого приложения,
затем **закрыть и заново открыть терминал**. OpenCV на macOS работает через AVFoundation
(`qonaq/sources/record.py`, `webcam_api()`); индекс встроенной камеры обычно `webcam:0`, iPhone через
Continuity Camera может оказаться `webcam:1`. На Windows используется DirectShow.

## 2. Как поставить ноутбук

- **Высоко и под углом**, как настоящая камера наблюдения: на шкаф/полку, экран наклонить вниз так, чтобы
  стол был в кадре целиком, а человек за столом — с головой и плечами. Минимум — стопка книг на соседнем столе.
- Стол — в **левой половине кадра** (так совпадёт зона по умолчанию; иначе см. п. 5).
- Свет ровный, без окна за спиной у гостя.
- Ноутбук на зарядке, отключить сон экрана.

## 3. Сценарий (по минутам)

«Официант» — в **заметно другой одежде** (фартук, тёмная рубашка), чем «гость».
Время — от старта записи (на экране ноутбука можно держать часы, команда сама печатает прогресс раз в 30 с).

| Время | Кто | Что делает |
|---|---|---|
| 0:00–1:00 | — | Пустой стол в кадре, **никого**. (Эталон пустого стола; стол не должен считаться «уже занятым».) |
| 1:00 | гость | Подходит и **садится** за стол, сидит спокойно. |
| 3:00 | официант | Подходит **стоя**, стоит у стола **20 с** (будто принимает заказ), уходит из кадра. |
| 5:00 | гость | Встаёт и **выходит из кадра** («покурить»). |
| 6:00 | гость | Возвращается и садится обратно. |
| 7:00 | гость | Ставит **чашку** на стол, уходит из кадра насовсем. |
| 7:00–10:00 | — | Пусто, чашка на столе (стол «не убран»). |
| 10:00 | официант | Подходит, **стоит 15 с**, забирает чашку, уходит. |
| 10:00–11:00 | — | Пусто. Запись заканчивается сама. |

Поэтому записываем **11 минут** (660 с), а не 10: после уборки нужна минута пустого стола.

## 4. Запись

```bash
python -m qonaq record --source webcam:0 --seconds 660 --out data/videos/staged.mp4
```

Добавьте `--preview`, чтобы видеть картинку (окно; `q` — остановить). Запись — без блюра: это тестовый
вход с согласия участников, лежит в `data/` (в `.gitignore`, в git не попадает). Всё, что из него
получается (демо-ролик, кадры), — с блюром.

## 5. Разметка (что было на самом деле)

Скопируйте шаблон в `data/gt/staged.yaml` и **поправьте времена** по факту (секунды от начала записи;
удобно смотреть запись в плеере). Точность ±10 с достаточна.

```yaml
video: staged.mp4
zones: configs/zones/staged.yaml
events:
  - {t: 60,  zone: T01, event: seated}
  - {t: 180, zone: T01, event: served}      # первый подход официанта
  - {t: 420, zone: T01, event: left}        # гость ушёл насовсем (уход «покурить» в 5:00 — не событие)
  - {t: 615, zone: T01, event: cleaned}     # конец уборки
alerts_forbidden: [no_waiter]               # официант пришёл через 2 мин < 3 мин
notes: постановка, 2 человека
```

Если в 5:00 гость отсутствовал дольше 90 с — это уже «ушли» по правилам системы; поправьте разметку.

## 6. Прогон и сверка одной командой

```bash
python -m qonaq staged-check data/videos/staged.mp4 --gt data/gt/staged.yaml
```

Что делает: берёт зоны из `configs/zones/staged.yaml`, если файла нет — автопредложение по детекциям, а если
столов не нашлось — одна зона на левую часть кадра; гонит пайплайн с боевыми порогами (`configs/sites/staged.yaml`);
пишет демо-ролик с блюром `runs/staged/demo.mp4`, отчёт `runs/staged/report.html`, сверку `runs/staged/eval.md`
и печатает «что поймано» по минутам.

Проверить зону до прогона: `runs/zones/staged.png` (создаётся командой). Поправить зону:

```bash
python -m qonaq zones edit data/videos/staged.mp4 --zones configs/zones/staged.yaml
```

и запустить `staged-check` ещё раз (файл зон теперь есть — он и используется).

Быстрее на слабом CPU: `--model yolox_s`. На Windows с RTX 2060 Super: `pip install "onnxruntime-gpu[cuda,cudnn]"` вместо
`onnxruntime` — YOLOX пойдёт на CUDA.

## 7. Что прислать обратно

`runs/staged/eval.md`, вывод «что поймано», `runs/staged/report.html`. Сам ролик `staged.mp4` не публиковать.
