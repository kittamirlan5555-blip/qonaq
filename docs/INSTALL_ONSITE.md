# Чек-лист установки на объекте

Цель выезда: за 1–2 часа получить работающую панель и первый журнал событий. Всё ниже — по порядку.

## До выезда

- [ ] Узнать у заказчика модель регистратора/камер (Hikvision, Dahua, XMeye, Uniview…) и есть ли
      свободный ПК. Без видеокарты — 1–2 камеры при 2 кадрах/с; с GTX 1660 / RTX 3050 — 4–8 камер.
- [ ] Попросить отдельную учётную запись на регистраторе **только на просмотр** (не admin).
- [ ] Попросить схему зала или фото: какие столы важны, где вход, где проход персонала.
- [ ] Подготовить ноутбук/мини-ПК: Python 3.11–3.12, проект, `pip install -e .`, `python -m qonaq doctor`.
- [ ] Договориться о среднем чеке на стол и часах работы — они нужны для отчёта.

## На месте: доступ к регистратору

- [ ] ПК и регистратор в одной локальной сети. Узнать IP регистратора (наклейка, меню «Сеть»,
      либо утилиты SADP для Hikvision / ConfigTool для Dahua).
- [ ] В веб-интерфейсе регистратора проверить, что **RTSP включён** (порт 554) и что у учётной записи
      есть право удалённого просмотра нужных каналов.
- [ ] Включить и настроить **substream** (второй поток): H.264, 640×360…704×576, 10–15 к/с.
      H.265+ / Smart-кодеки лучше выключить на субпотоке — с ними бывают артефакты.
- [ ] Помнить про лимит одновременных подключений к регистратору: если уже смотрят с телефонов,
      наш поток может не открыться. Субпоток обычно свободнее основного.

## Проверка RTSP через VLC

- [ ] VLC → «Медиа» → «Открыть URL» → вставить адрес из `configs/examples/rtsp_templates.yaml`.
      Hikvision: `rtsp://USER:PASS@IP:554/Streaming/Channels/102` (канал 1, субпоток).
      Dahua: `rtsp://USER:PASS@IP:554/cam/realmonitor?channel=1&subtype=1`.
- [ ] Картинка идёт без рассыпаний 2–3 минуты. Если нет — проверить пароль (спецсимволы в пароле
      надо кодировать в URL), номер канала, включён ли RTSP.
- [ ] Для каждой камеры оценить глазами: сколько столов видно целиком, какие перекрыты.
      Камеры ставили «для охраны», часть столов будет не видна — **это нормально, честно записываем покрытие**.

## Настройка системы

- [ ] `.env`: `CAM_USER`, `CAM_PASS`, при необходимости `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
      Пароли в YAML и в git не попадают.
- [ ] `configs/sites/<объект>.yaml`: скопировать пример, вписать камеры (`source: rtsp://${CAM_USER}:${CAM_PASS}@...`),
      профиль (`restaurant` или `clinic`), средний чек, часы работы.
- [ ] Зоны: сохранить кадр с каждой камеры (в **пустом** зале лучше всего), затем
      `python -m qonaq zones suggest <кадр>` → `python -m qonaq zones edit <кадр>`.
      Полигон стола — стол вместе со стульями; на косой камере поднять верхнюю границу выше столешницы,
      чтобы сидящие попадали в зону целиком. Проход персонала, кухню, телевизор — в `ignore`.
- [ ] `python -m qonaq live --site configs/sites/<объект>.yaml` → открыть панель `http://127.0.0.1:8000`.
- [ ] 15 минут смотреть панель вместе с администратором: совпадают ли статусы столов с тем, что в зале.
      Расхождения записать (какой стол, что было на самом деле) — это материал для настройки зон и порогов.
- [ ] Калибровка формы персонала (если форма есть): `python -m qonaq roles calibrate <запись>`,
      выбрать id сотрудников, прописать `roles.staff_profile` в YAML объекта.

## Автозапуск

**Windows** — Планировщик заданий: «Создать задачу» → триггер «При запуске компьютера» →
действие: программа `C:\qonaq\.venv\Scripts\python.exe`, аргументы
`-m qonaq live --site configs\sites\<объект>.yaml`, рабочая папка `C:\qonaq`.
Отметить «Выполнять независимо от входа пользователя» и «Перезапускать при сбое».
Альтернатива — NSSM (служба Windows с автоперезапуском).

**Linux** — systemd, файл `/etc/systemd/system/qonaq.service`:

```ini
[Unit]
Description=Qonaq Vision
After=network-online.target

[Service]
WorkingDirectory=/opt/qonaq
ExecStart=/opt/qonaq/.venv/bin/python -m qonaq live --site configs/sites/<объект>.yaml
Restart=always
RestartSec=10
User=qonaq

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now qonaq
```

- [ ] Перезагрузить ПК и убедиться, что система поднялась сама и панель открывается.
- [ ] Выключить и включить регистратор: поток должен восстановиться сам в течение минуты.
- [ ] В BIOS/настройках питания: включаться после пропадания электричества, не засыпать.

## Что сказать персоналу

- Система **не распознаёт лица** и не знает, кто есть кто. Она видит «за столом 4 сидят люди» и
  «к столу подошли».
- Видео не записывается и никуда не отправляется — оно и так пишется вашим регистратором, мы его
  только анализируем на месте. Наружу уходят цифры: сколько ждали, сколько стол стоял неубранным.
- Цель — не наказать конкретного официанта, а увидеть, где залу не хватает рук: в какие часы,
  на каких столах. Сильным сотрудникам объективные цифры выгодны.
- Первая неделя — «тихий» сбор без алертов (базовая линия). Потом включаются уведомления администратору.
- Табличка «Ведётся видеонаблюдение» должна быть на входе (обычно уже есть).

## Клиника: дополнительно

- Пациенты — особо чувствительная категория. Только агрегаты; **никаких сохранённых кадров и роликов
  с людьми без размытия**, а лучше не сохранять вовсе.
- Согласовать установку с руководством и ответственным за персональные данные.
- Зоны: `waiting_area` — где сидят и ждут; `service_point` — где посетитель стоит у регистратуры,
  плюс `staff_polygon` — где находится сотрудник за стойкой (нужно для алерта «очередь без сотрудника»).

## Перед уходом

- [ ] Записать: IP регистратора, каналы, какие столы покрыты, какие нет, версию конфигов (git commit).
- [ ] Оставить администратору адрес панели и объяснить три цвета: жёлтый — ждут, синий — обслуживаются,
      оранжевый — не убрано; красный — пора вмешаться.
- [ ] Договориться о дате первого отчёта «как есть» (через неделю).
