# SPRINT2 — к первому пилоту (главнее WEEKEND_PLAN.md и TASKS.md)

Цель спринта: всё, что можно сделать **без владельца и без живой камеры**, чтобы первый пилот в ресторане
прошёл гладко: установка за 2–4 часа, работа неделями без присмотра, понятный отчёт владельцу заведения,
материалы для продаж. Владелец не отвечает: вопросов не задавай, решения — в `DECISIONS.md`.

## Протокол сессии (обязательно)

1. Ветка `claude/bold-fermat-de51i5`, `git pull`. Если последний коммит моложе 20 минут — работает другая
   сессия: заверши работу. Если первая строка `PROGRESS.md` — «ВСЕ ЗАДАЧИ SPRINT2 ВЫПОЛНЕНЫ» — заверши работу.
2. Прочитай `CLAUDE.md`, `PROGRESS.md`, этот файл, `DECISIONS.md`, `docs/EVAL.md` §13. Продолжи с первой задачи
   не в статусе ✅.
3. Окружение как раньше: `.venv`, `pip install -e ".[dev]"`, без torch/ultralytics, YOLOX через onnxruntime,
   `scripts/fetch_videos.py`, при необходимости `fetch_datasets.py` и `fetch_models.py`.
4. Коммить и пушь не реже раза в 30–40 минут. Перед коммитом — `pytest` и `ruff check`.
5. После каждой задачи — статус здесь и раздел в `PROGRESS.md`; цифры — в `docs/EVAL.md` (новые разделы с §14).
6. Не коммить видео, датасеты, `runs/`, бинарники. Кадры и видео с людьми — только с блюром.
7. Никаких выдуманных цифр; про то, что не проверено, так и пиши.
8. Когда все задачи ✅ — первая строка `PROGRESS.md`: «ВСЕ ЗАДАЧИ SPRINT2 ВЫПОЛНЕНЫ».

Вне спринта: clinic, iiko/r_keeper/Poster, университет, LLM-отчёты.

## S1. Камеры по RTSP

- Поставь MediaMTX (бинарник из GitHub releases bluenviron/mediamtx, не коммитить) и ffmpeg (есть через
  imageio-ffmpeg). Отдавай ролики зацикленно как камеры с путями, как у реальных регистраторов:
  Hikvision `/Streaming/Channels/102`, Dahua `/cam/realmonitor?channel=1&subtype=1` (если путь с query не
  поддерживается сервером — задокументируй и проверь хотя бы Hikvision-вид), с логином/паролем.
- `configs/sites/rtsp_emulated.yaml`: 4 камеры. Прогон `live` 4 камер одновременно ≥ 60 минут: fps по каждой,
  CPU, RSS-память в начале/конце (утечки), задержка кадра. Обрыв: убей сервер на 2 минуты и подними —
  `live` должен переподключиться сам, health должен показать обрыв, события не должны поломаться.
- Скрипт `scripts/emulate_cameras.py` (кросс-платформенный) — чтобы владелец мог повторить у себя.
- Цифры — EVAL §14. Если что-то течёт или падает — почини.

## S2. Детектор для тёмных угловых камер

Проблема из EVAL: на `cctv_restaurant_corner` `yolox_s` почти не видит людей, `yolox_m` + плитки не успевает.
- Меряй recall людей на кадрах этого ролика (разметь руками 30–40 кадров bbox людей, файл в tests/fixtures) и
  fps на CPU для вариантов: yolox_s/m с плитками 1/2/3; плитки только по области зон столов (ROI, а не весь
  кадр); пропуск кадров для детектора при трекинге между ними; INT8-квантизация onnxruntime; при наличии
  ONNX-моделей с разрешительной лицензией (Apache-2.0/MIT) на GitHub — RT-DETR/D-FINE/RTMDet. Лицензию проверяй.
- Выбери профили по умолчанию: «CPU мини-ПК 2–4 камеры» и «GPU (RTX 2060) 8 камер» — с цифрами, что ожидать.
  Документируй, как включить onnxruntime-gpu / DirectML на Windows.
- Цифры — EVAL §15, решение — DECISIONS.

## S3. Установка на мини-ПК

- `python -m qonaq setup`: интерактивно и флагами (`--nvr-ip --user --password --vendor auto`):
  перебирает RTSP-шаблоны Hikvision/HiWatch, Dahua/Imou, Uniview, XMeye (из docs/KZ_REALITIES.md) по каналам,
  при возможности ONVIF WS-Discovery в локальной сети, снимает кадр с каждой найденной камеры (с блюром),
  пишет `configs/sites/<site>.yaml` (пароль — в `.env`), запускает `zones suggest` по каждой камере.
  Проверь на эмуляции из S1.
- Служба: Linux — systemd unit + команда установки; Windows — скрипт через Планировщик задач (или NSSM, если
  удобнее) с автоперезапуском. `qonaq service install|status|uninstall`.
- Удалённый доступ: инструкция Tailscale + SSH (Linux и Windows), как запускать Claude Code на мини-ПК по SSH.
- `docs/PILOT_RUNBOOK.md`: до установки (что попросить у заведения: пароль регистратора, место для ПК, кабель),
  день установки по шагам с временем, ежедневная проверка, неделя 1 тихий сбор, калибровка, неделя 2 отчёт,
  недели 3–4 алерты, финальная встреча; что делать, если камера/сеть/ПК отвалились.
- Рекомендация по железу мини-ПК (минимум и комфорт) на основе цифр S1–S2, без конкретных цен.

## S4. Telegram

- Подними локальный фейковый Telegram Bot API (маленький сервер на FastAPI с тем же форматом sendMessage /
  sendPhoto / answerCallbackQuery / getUpdates), направь на него клиента через настройку базового URL.
  Проверь: алерт администратору, кнопка «Неверно» (callback → запись в feedback), сводка смены владельцу заведения,
  ежедневная техническая сводка тебе, очередь при обрыве сети и дедупликация.
- Финальные тексты сообщений по-русски: коротко, с номером стола и временем, без технических слов.
  Примеры всех сообщений — в `docs/TELEGRAM.md`, плюс инструкция BotFather → токен → chat id → `.env`
  и команда `python -m qonaq telegram test`.

## S5. Отчёт пилота

- `python -m qonaq report pilot --baseline <период/прогоны> --after <период/прогоны>`: HTML для владельца
  заведения, по-русски, без техники: медиана и p90 подхода официанта, доля ожиданий > 3 минут, простой
  неубранных столов в часы пик, посадки, оценка потерь в ₸ (консервативно, только пик, с формулой мелким
  шрифтом), сравнение «как есть / стало», худшие часы и столы, оговорки о точности и калибровке.
- Проверь на синтетике (сделай «неделю как есть» и «неделю после» из сценариев synth с разными параметрами).
- Пример отчёта (на синтетике, с пометкой) — `docs/examples/pilot_report_example.html`.

## S6. Продажи

Всё по-русски, для Астаны, без обещаний точности, которых нет.
- `docs/sales/ONE_PAGER.md` + печатный HTML: что это, что видит владелец, приватность (видео не уходит, лиц нет),
  как проходит бесплатный пилот, что нужно от заведения.
- `docs/sales/CONVERSATION.md`: первые вопросы владельцу/управляющему (сначала про боли, не про продукт),
  ответы на возражения («у меня менеджер следит», «дорого», «персонал против», «а законно ли», «а если ошибается»),
  как предложить пилот, как закончить пилот разговором о цене.
- `docs/sales/PILOT_AGREEMENT_TEMPLATE.md`: простое соглашение о бесплатном пилоте (что делаем, срок, данные,
  без распознавания лиц, оборудование, конфиденциальность) с пометкой «проверить у юриста перед использованием».
- `python -m qonaq demo-reel`: 30–45-секундный ролик из синтетики полного цикла (с панелью и подписями-титрами
  «гости сели», «ждут 3:10 → алерт», «официант подошёл», «стол не убран») + кусок реального CCTV веранды,
  всё с блюром; явная плашка «демонстрация на тестовых данных».
